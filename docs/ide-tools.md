# IDE tools

**`bin/ide`** — opens the appropriate IDE (VS Code or IntelliJ IDEA) for the git root of a given path or file (or `$PWD`), and with `path:line[:column]` the file at that line: after opening the project, VS Code gets `--goto file:line:col` and IntelliJ gets `open idea://open?file=<url-encoded path>&line=N[&column=M]`, which the running instance handles (IntelliJ opens a file in LightEdit rather than in its project unless the project is already open, hence the `IDE_JUMP_DELAY` seconds, default 1, between the two steps; `--args --line` on `open -a` is dropped when IntelliJ is already running, and the Toolbox shim wraps paths with spaces in literal quotes). The file is resolved through symlinks first, because IntelliJ doesn't recognise a symlinked path as inside the open project. A path that exists with a colon in its name is a path, not `path:line`; a line on a directory or a missing file is an error. Tested by `zsh/functions/ide-tests.zsh` against fake `code` and `open`. Detects the IDE from project files: IntelliJ for `pom.xml`, `build.gradle`, `build.gradle.kts`, `go.mod` or `.idea`, VS Code otherwise. A running IDE is reused rather than relaunched: VS Code via `code --reuse-window`, IntelliJ via `open -a "IntelliJ IDEA"`, not the Toolbox `idea` shim, whose `open -n` starts a whole extra IntelliJ process per call. For a project with a `package.json` it first selects an nvm Node matching `.nvmrc` or `engines.node`, because it doesn't source `~/.zshrc` and may otherwise launch the IDE with no nvm Node on `PATH`.

**`bin/close-project`** — inverse of `ide`: closes the IDE window for a given project path (or `$PWD`). When called with no argument, also closes the current kitty pane. Uses `System Events` + close-button click for VS Code (no AppleScript dictionary).

**`bin/project-web`** — opens the web page for a project (git root of a given path, or `$PWD`) in the browser. Before opening anything, checks via AppleScript whether a Microsoft Edge tab already has that repo's URL (or a sub-page under it, e.g. an open issue/PR) open, and if so focuses that tab/window instead of opening a new one. Otherwise derives an `https://` URL for the project root from the origin remote (handling both `git@host:owner/repo.git` and `https://host/owner/repo.git` forms) and `open`s it. It deliberately doesn't use `glab`/`gh repo view -w`: those need an API token (`glab` goes through `op plugin run`, which prompts for Touch ID), and `glab` opens `/-/tree/<current branch>`, which 404s when the branch hasn't been pushed.

**`bin/hunk-dock [--close] [DIR]`** — reviews `DIR`'s (default `$PWD`) changes in Hunk (`hunk diff --watch`) in a kitty 0.50 window-dock at the top of the calling window's tab (`--match=window_id:$KITTY_WINDOW_ID`), 65% high, without taking focus, titled `hunk`. `HUNK_DOCK_EDGE` / `HUNK_DOCK_SIZE` override edge and size; a dock can't be resized after launch, so `--close` and reopen. Idempotent: a window titled `hunk` whose cwd is `DIR` is reported (its id printed), not duplicated. Docks are saved in sessions and close with their host window, so `save-session` needs no special handling. No key binding: Claude runs it, then drives Hunk with the `hunk-review` skill. Design: `docs/superpowers/specs/2026-11-04-named-tabs-and-hunk-dock-design.md`.

**`bin/btop-dock [--close]`** — a btop strip along the bottom of the calling window's tab: a kitty 0.50 tab-dock (`--dock-edge=bottom --dock-size=25% --dock-skip-focus`), so the layout arranges the other windows above it and it never takes keyboard focus (display-only — `--close` is how to remove it). Saved in sessions; closes with the tab's last real window. It runs btop on a copy of your `btop.conf` (written to `~/.cache/project-tools/btop-dock.conf` at each launch) with `shown_boxes` cut to `cpu`: btop with all four boxes needs 24 rows and refuses to draw in less, while the cpu box fits in about 10. `BTOP_DOCK_BOXES` chooses other boxes; `BTOP_DOCK_EDGE` / `BTOP_DOCK_SIZE` override edge and size (a dock can't be resized after launch: `--close` and reopen). Idempotent per tab: a window titled `btop` already in the calling window's tab is reported (its id printed), not duplicated. No key binding.
